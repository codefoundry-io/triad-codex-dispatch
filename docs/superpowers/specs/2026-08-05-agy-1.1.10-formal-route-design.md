# AGY 1.1.10 Formal Route Design

> **Status:** Historical, superseded, and non-executable. This 0.2.532 design
> record does not direct current dispatch or release work. Current authority is
> the [0.2.533 completion plan](../plans/2026-08-05-triad-0.2.533-owner-decisions-and-release.md)
> and the [active leg contract](../../../skills/triad-cross-family-review/references/leg-contracts.md):
> one focused Google leg uses `--model gemini-3.1-pro-high --effort high` and
> makes one provider call.

## Objective

Adopt AGY 1.1.10's repaired headless model-selection contract for the formal
Google-family review route without changing the generic wrapper transport or
inventing model normalization.

## Observed evidence

The owner login shell resolved `/Users/chaniri/.local/bin/agy` at version
`1.1.10`. The installed `agy changelog` states that this release fixes
`--model` and `--effort` being applied after model configuration in both
interactive and headless `-p` runs, which previously allowed the persisted or
default model to win silently. It also fixes a bare `--effort` resolving
against the default model instead of the selected model.

Authenticated `agy models` advertised `gemini-3.1-pro-high`. Three independent
headless `stream-json` probes completed successfully:

| Requested route | Exit | `init.model` | Marker |
|---|---:|---|---|
| `--model gemini-3.1-pro-high` | 0 | `gemini-3.1-pro-high` | `AGY_110_SLUG_OK` |
| `--model gemini-3.1-pro --effort high` | 0 | `gemini-3.1-pro` | `AGY_110_BASE_EFFORT_OK` |
| `--model "Gemini 3.1 Pro (High)"` | 0 | `Gemini 3.1 Pro (High)` | `AGY_110_DISPLAY_OK` |

This differs from the preserved AGY 1.1.7 evidence: that build advertised the
stable slug but silently routed the slug candidates to a different default
model. The 1.1.10 vendor fix and structured runtime identity remove the reason
for the display-label compatibility route.

A fresh-context baseline using the current shipped skill still selected the
display label and explicitly declined a 1.1.10 floor. That is the reproducible
policy defect this change corrects.

## Selected design

Use `--model gemini-3.1-pro-high` with no separate `--effort` for every formal
AGY leg. Before formal dispatch, require all of the following:

1. authenticated `agy --version` reports `1.1.10` or newer;
2. authenticated `agy models` contains the exact
   `gemini-3.1-pro-high` selector;
3. the wrapper preflight records the exact slug and no effort;
4. provider acceptance succeeds, and any exposed runtime identity agrees with
   the requested slug.

An older, unprobeable, missing-selector, rejected, or identity-conflicting AGY
route leaves the required Google family unavailable. It never activates a
silent display-label compatibility route or a same-round provider
substitution.

Keep `antigravity_wrapper.py` as a generic exact passthrough. It continues to
accept free-form `--model` and optional `--effort` values for non-formal use.
The formal skill owns the versioned route policy; the wrapper does not rewrite
selectors, infer an effective model, or choose version-dependent fallbacks.

## Alternatives rejected

### Documentation-only route switch without a floor

Rejected because AGY 1.1.7 is already proven to accept the slug while routing
it to the wrong model. Catalog presence and process success alone are not a
safe compatibility boundary.

### Wrapper normalization or version-dependent fallback

Rejected because hidden rewriting would make the receipt differ from the
owner-selected argv and could conceal a provider regression. Exact
passthrough plus a fail-closed formal policy keeps selection auditable.

### Keep the display-label control indefinitely

Rejected because it ignores the vendor's repaired stable-slug contract and
retains an undocumented compatibility spelling as the production route.
