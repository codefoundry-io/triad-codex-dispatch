## Limits

AGY read-tool availability and alias behavior are attributed to the shared host-A
record, not a fresh Codex live probe. Existing profile names resolve the canonical
read alias without adding duplicate names. Exposed `manage_task` is refused after
observation; refusal cannot prevent or roll back an executed effect.

`done_view_file_event_count` keeps its historical name and counts both aliases.
It is bounded diagnostic data, not proof of successful packet reads. Shared
prompt updates remain upstream DL-180; the operator binds current capabilities,
uses only offered native tools and discloses inaccessible necessary coverage.
Search summaries/redirects are pointers; decisive claims require original-page
verification. No unpublished library revision is silently adopted.

## Bounded native task-event observation

On 2026-11-08, local `agy --version` reported `1.5.3`. A fresh raw CLI invocation
used `--mode plan --sandbox --model gemini-4-argon-high --effort high`, no custom
agent, and requested exactly `manage_task` with `Action=list`, then finish. It
requested no creation, cancellation, input, file access, web or delegation.
Vendor exit was 0 and the terminal status was SUCCESS. The observed task step
had `step_type=tool`, both `tool_name` and `tool_info.name` equal to `manage_task`,
parameters `{"Action":"list"}`, and ACTIVE then DONE states with no tool error.
The earlier packaged-profile invocation refused the request without calling the
tool; it is not evidence of task execution or vendor enforcement.

[The projected fixture](../../tests/fixtures/agy153-manage-task-list.jsonl)
retains the observed containment-relevant fields and parameters. Conversation
identifiers, timing, free text and task-list output are omitted. The fixture
SHA-256 is `243265f20622fcdd895740fb2b7987e75bbf65ae4dc484bf779d095621fd61fa`;
the original stream SHA-256 is
`4a10c7397367dd05c5fe4aef1233c6d357e98f8d08cb709a8d24100205704ac8`.
Replay adds a constructed terminal verdict and asserts refusal; it does not
claim that the diagnostic itself was a formal review. This single list-action
observation establishes the emitted fields for that invocation, not universal
tool-shape stability, prevention of effects, or behavior of mutating actions.

Subsequent review also reproduced duplicate-member normalization hiding a task
name. Read-only event parsing retains duplicate evidence before admission;
schema calls preserve `schema-fail` diagnostics and raw read-only calls refuse
with `admission-refused`. Primary authentication, timeout and transport guards
remain earlier. Undecodable events are conservatively refused even without a
terminal result; the separate task-operation check requires a terminal result.
AGY auth-carrier decoding also rejects duplicate members and nonfinite numbers on every route, so
early transport and signal checks cannot turn ambiguous events into auth stops.
Real independent authentication carriers retain priority.
Read-only event validation uses original lines and retains schema diagnostics
for duplicate members, nonfinite numbers and non-JSON surrounding whitespace.
The prior permissive completed-answer/banner veto is separate from positive
authentication evidence and never bypasses read-only event admission.

AGY stdout retains original LF record boundaries through byte capture and saved
run logs. Schema status and payload selection share original LF records.
Schema-free permissive parsing and the completed-answer/banner veto use a separate
normalized view. On UTF-8 capture failure, only complete LF-delimited prefix
records remain eligible for authentication; an incomplete record is not repaired
by truncation. Other providers retain their existing newline handling.
Task denial correlation also requires the same terminal-result segment and
matching nonempty conversation identity when exposed; both identifiers absent
retains legacy correlation. One-sided, malformed or conflicting identities do
not prove denial. These edge cases are synthetic regression coverage, not claims
about additional observed AGY behavior.

Synthesized result-status text is diagnostic only: provider classification uses
captured stderr and the typed terminal carrier. Conflicting exposed tool names
can indicate a task attempt but cannot prove its denial; both correlated records
need consistent names and cannot contradict each other’s exposed parameters.
Missing parameter diagnostics remain compatible. Schema diagnostics retain
duplicate/nonfinite evidence already decoded before trailing non-JSON whitespace.

Borrowing denial requires one coherent set of exposed parameter values across
all task observations sharing the result segment, exact integer index and
compatible conversation identity. Missing fields cannot hide contradictory
observations; identical progress repeats remain compatible. Wrapped command
permission-check failures are not task pre-execution denial evidence. Generic
native denial heads remain eligible; command finish recovery is unchanged.
These are conservative evidence rules, not measured vendor-wide task lifecycles.
