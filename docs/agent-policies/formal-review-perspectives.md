# TRIAD repository formal-review perspectives

This project operating policy selects guarded existing-worktree review under the
temporary workspace five-leg overlay. It does not change the public TRIAD
three-family contract or `LegVerdict` schema. The root leader reads the workspace
overlay and translates these lenses into its tested prompt helper; reviewers do
not receive or cite governance files. Each leg still performs the complete review.

## Focus A: CLI and runtime contracts

Inspect the approved changed code and its exact Python 3.12+/Bash bootstrap and
wrapper call paths. Check explicit bootstrap Codex-root precedence, legacy
`CODEX_HOME` compatibility, canonical absolute-path/containment validation, and
provenance-matched target selection without changing login or provider state.
For formal wrapper changes, verify the bound Claude `opus`/`xhigh`/1200-second
route, AGY `gemini-3.1-pro-high`/`high`/600-second route and derived child timeout,
or selected Gemini Auto/600-second route against actual argv and fail-closed
pre-provider validation. Check selector/preflight executable, model, review-ID,
and digest bindings; do not infer runtime identity from an unexposed field.

## Focus B: result and integrity ownership

Inspect reuse of existing validation, cleanup, and process contracts rather than
new parallel control paths. Check that bootstrap's selected Codex directory owns
all matching checks/cleanup and preserves non-matching owner bytes. For wrapper
changes, inspect terminal-result ownership: an observation wake-up is not a
provider failure, while the route-owning process deadline and strict local verdict
binding determine the actual terminal outcome. Keep captured results provisional
until matching post-review integrity; no result, retry, route switch, or sibling
output may silently replace required evidence. Enforce the current approved
one-behavioral-claim boundary, without requesting adjacent generalization.

## Custody and cleanup

Keep current task/status/diff custody under the existing worktree's ignored
`_runs/review-custody/<review_id>/`; keep prompts, results, logs, ledger and focus
text separately in the workspace root's `_runs/reviews/<review_id>/`. Preserve
durable evidence there. After terminal collection, integrity and adjudication,
remove only the exact current source-SOT temporary stage/cwd handles. Do not
delete historical custody, ignored work, or unrelated worktrees.
